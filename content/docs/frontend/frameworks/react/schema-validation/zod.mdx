Zod — это библиотека для JavaScript и TypeScript, которая проверяет, соответствуют ли данные заданной структуре (схеме).<br/>
Zod помогает убедиться, что данные имеют правильный тип и формат, прежде чем использовать их в программе.

- Валидация форм — проверка email, паролей и других полей.
- Проверка API — проверка данных, полученных от сервера.
- Валидация запросов — проверка входных данных перед обработкой.
- TypeScript — автоматическое получение типов из схем, чтобы не описывать их дважды.

## Использование

```ts
import { z } from "zod";
```

Создаём схему валидации данных.

<Callout>Схема — это описание того, каким данным можно доверять.</Callout>

```ts
const UserSchema = z.object({
  name: z.string(),
  age: z.number(),
  email: z.email(),
});
```

Проверяем данные:

```ts
const user = UserSchema.parse({
  name: "Alex",
  age: 25,
  email: "alex@example.com",
});

console.log(user.name); // "Alex"
```

<details>
  <summary>Пример когда объект не пройдет валидацию</summary>

Здесь сразу две проблемы: `age` — строка вместо числа, а `email` имеет неправильный формат. `parse()` выбросит исключение `ZodError`, содержащее информацию об ошибках.

```ts
UserSchema.parse({
  name: "Alex",
  age: "25",
  email: "not-an-email",
});
```

</details>

## Основные типы схем и их ограничения

### Object (`z.object()`)

Проверяет объект с заданными полями

| Метод               | Описание                            | Пример                             |
| ------------------- | ----------------------------------- | ---------------------------------- |
| `.extend(shape)`    | Добавляет или переопределяет поля   | `User.extend({ age: z.number() })` |
| `.pick(shape)`      | Выбирает поля                       | `User.pick({ name: true })`        |
| `.omit(shape)`      | Исключает поля                      | `User.omit({ password: true })`    |
| `.partial()`        | Делает все поля необязательными     | `User.partial()`                   |
| `.required()`       | Делает поля обязательными           | `User.required()`                  |
| `.strict()`         | Отклоняет неизвестные ключи         | `User.strict()`                    |
| `.catchall(schema)` | Проверяет дополнительные ключи      | `User.catchall(z.string())`        |
| `.refine(fn)`       | Добавляет пользовательскую проверку | `User.refine((u) => u.age >= 18)`  |

<hr />

### String (`z.string()`)

Проверяет строку

| Метод            | Описание                           | Пример                           |
| ---------------- | ---------------------------------- | -------------------------------- |
| `.min(n)`        | Минимальная длина                  | `z.string().min(3)`              |
| `.max(n)`        | Максимальная длина                 | `z.string().max(100)`            |
| `.length(n)`     | Точная длина                       | `z.string().length(6)`           |
| `.nonempty()`    | Не пустая строка                   | `z.string().nonempty()`          |
| `.regex(regex)`  | Соответствие регулярному выражению | `z.string().regex(/^[a-z]+$/)`   |
| `.startsWith(s)` | Начинается с подстроки             | `z.string().startsWith("user_")` |
| `.endsWith(s)`   | Заканчивается подстрокой           | `z.string().endsWith(".com")`    |
| `.includes(s)`   | Содержит подстроку                 | `z.string().includes("@")`       |
| `.uppercase()`   | Только верхний регистр             | `z.string().uppercase()`         |
| `.lowercase()`   | Только нижний регистр              | `z.string().lowercase()`         |

Дополнительные преобразования строк:

| Метод            | Описание                      | Пример                     |
| ---------------- | ----------------------------- | -------------------------- |
| `.trim()`        | Удаляет пробелы по краям      | `z.string().trim()`        |
| `.toLowerCase()` | Преобразует в нижний регистр  | `z.string().toLowerCase()` |
| `.toUpperCase()` | Преобразует в верхний регистр | `z.string().toUpperCase()` |
| `.normalize()`   | Нормализует Unicode           | `z.string().normalize()`   |

### Number (`z.number()`)

Проверяет число

| Метод            | Описание                  | Пример                     |
| ---------------- | ------------------------- | -------------------------- |
| `.min(n)`        | Минимум, включая границу  | `z.number().min(0)`        |
| `.max(n)`        | Максимум, включая границу | `z.number().max(100)`      |
| `.gt(n)`         | Строго больше             | `z.number().gt(0)`         |
| `.gte(n)`        | Больше или равно          | `z.number().gte(18)`       |
| `.lt(n)`         | Строго меньше             | `z.number().lt(100)`       |
| `.lte(n)`        | Меньше или равно          | `z.number().lte(100)`      |
| `.positive()`    | Больше нуля               | `z.number().positive()`    |
| `.nonnegative()` | Не меньше нуля            | `z.number().nonnegative()` |
| `.negative()`    | Меньше нуля               | `z.number().negative()`    |
| `.nonpositive()` | Не больше нуля            | `z.number().nonpositive()` |
| `.int()`         | Безопасное целое число    | `z.int()`                  |
| `.multipleOf(n)` | Кратно заданному числу    | `z.number().multipleOf(5)` |
| `.step(n)`       | Шаг / кратность           | `z.number().step(0.5)`     |

### Enum (`z.enum()`)

| Метод              | Описание                     | Пример                                        |
| ------------------ | ---------------------------- | --------------------------------------------- |
| `.exclude(values)` | Исключает значения из набора | `z.enum(["a", "b", "c"]).exclude(["c"])`      |
| `.extract(values)` | Оставляет выбранные значения | `z.enum(["a", "b", "c"]).extract(["a", "b"])` |

Enum изначально ограничивает значения перечисленным набором, поэтому отдельный `.min()` или `.max()` ему не нужен.

## Необязательные поля, `null` и значения по умолчанию

### `optional()`

Тип или `undefined`; поле можно не передавать

### `nullable()`

Тип или `null`; поле должно присутствовать

### `nullish()`

Тип, `null` или `undefined`

Если значение `undefined`, подставляется `value`

## Парсинг

### `parse()`

Использовать, когда при неправильных данных нужно выбросить ошибку и передать её обработчику исключений.

```ts
const data = MySchema.parse(input);
```

Если данные невалидны, выполнение перейдёт в catch, если исключение не перехвачено раньше.

#### `parseAsync(data)`

```ts
schema.parseAsync(data);
```

<hr />

### `safeParse()`

Возвращает результат с признаком успеха.

```ts
const result = MySchema.safeParse(input);

if (result.success) {
  console.log(result.data);
} else {
  console.log(result.error.issues);
}
```

Результат имеет два варианта:

- `success: true` — данные находятся в `result.data`.
- `success: false` — ошибки находятся в `result.error.issues`.

#### `safeParseAsync(data)`

```ts
schema.safeParseAsync(data);
```

## `z.infer<typeof NameSchema>` Автоматическое получение типов

```ts
const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
  email: z.email(),
});

type User = z.infer<typeof UserSchema>;
```

TypeScript автоматически получает такой тип:

```ts
type User = {
  id: number;
  name: string;
  email: string;
};
```

## Ошибка

### `parse()`

В Zod ошибка при `.parse()` ловится через `try...catch`, потому что `.parse()` выбрасывает исключение `ZodError`, если данные не прошли проверку.

```ts
try {
  const user = UserSchema.parse({
    name: "Alex",
    age: "25",
  });
} catch (error) {
  if (error instanceof z.ZodError) {
    console.log(error.issues);
  }
}
```

Получить сообщения об ошибках:

```ts
  if (error instanceof z.ZodError) {
    for (const issue of error.issues) {
      console.log(issue.path);    // Путь к полю
      console.log(issue.message); // Сообщение об ошибке
      console.log(issue.code);    // Код ошибки
    }
```

<hr />

### `safeParse()`

```ts
if (!result.success) {
  console.log(result.error); // Ошибка Zod
  console.log(result.error.issues); // Массив ошибок
} else {
  console.log(result.data); // Проверенные данные
}
```

<hr />

### Кастомное сообщение об ошибке

В Zod 4 кастомное сообщение об ошибке можно передать через параметр `error`. <br/>
В Zod 4 вместо `message` рекомендуется использовать `error`, но `message` всё ещё поддерживается в большинстве валидаторов для обратной совместимости.

1. Для типов

   ```ts
   const nameSchema = z.string({
     error: "Имя должно быть строкой",
   });

   const ageSchema = z.number({
     error: "Возраст должен быть числом",
   });
   ```

2. Для ограничений

   ```ts
   const passwordSchema = z
     .string()
     .min(8, {
       error: "Пароль должен содержать минимум 8 символов",
     })
     .max(32, {
       error: "Пароль не должен превышать 32 символа",
     });
   ```

#### Динамическое сообщение

Можно передать функцию, которая получает информацию об ошибке:

```ts
const ageSchema = z.number({
  error: (issue) =>
    issue.input === undefined
      ? "Возраст обязателен"
      : "Возраст должен быть числом",
});
```
