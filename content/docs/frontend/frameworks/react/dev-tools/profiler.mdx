**Profiler** отвечает на вопрос «Как приложение рендерилось?».

Он используется для анализа производительности.

## Как работает

1. Открываешь вкладку Profiler.
2. Нажимаешь Record.
3. Выполняешь действия в приложении.
4. Нажимаешь Stop.

После этого появляется информация обо всех рендерах.

## Настройка

### Record why each component rendered while profiling

включает запись причин рендера каждого компонента во время профилирования.

## Commit

— это момент, когда React применяет результаты рендера к экрану (DOM).

Цвета помогают быстро понять, какие компоненты были дорогими по времени рендера:

- 🟦 Синий — компонент рендерился очень быстро.
- 🟩 Зеленый — рендер занял немного больше времени, но это нормально.
- 🟨 Желтый — рендер уже достаточно дорогой, стоит обратить внимание.
- 🟥 Красный — самый дорогой рендер. Именно такие компоненты чаще всего становятся причиной проблем с производительностью.

## Commit information

содержит сводную информацию о выбранном commit (обновлении интерфейса).

### Priority

:::warning
В React 18+ разные обновления могут иметь разный приоритет (обычные, пользовательские, фоновые и т.д.). <br/>
В React 18+ приоритеты используются планировщиком React для более плавной работы интерфейса.
:::

Показывает приоритет обновления.

### Committed at

Показывает момент завершения commit относительно начала записи Profiler.

### Durations

Это информация о времени выполнения commit.

- Render -> сколько времени заняла render-фаза
- Layout effects -> время затраченное на синхронные эффекты коммиты фазы
- Passive effects -> асинхронные после Layout (такик как useEffect)

### What caused this update

Он отвечает на вопрос:

- Почему вообще произошел этот commit?

Profiler показывает источник обновления.
