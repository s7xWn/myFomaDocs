**_Компонент_** — это независимая часть интерфейса веб-приложения, часто рассчитанная на повторное использование. Компонент может иметь любое содержимое — от отдельного элемента страницы (наподобие кнопки) до целого экрана приложения (компонент-экран) — и быть сколь угодно сложным.<br/>
**_Компонент приложения_** выводится на страницу сразу после запуска приложения и вмещает в себя весь его интерфейс.

## Function Components

:::danger[Важно]
Имя компонента должно начинаться с большой буквы (это обязательно!)

Если имя компонента состоит из нескольких слов, каждое из них должно начинаться с большой буквы (TodoList, TodoDetail, TodoAdd)

Такой стиль именования сущностей в программном коде называется **PascalCase**;
:::

В теле компонента можно объявлять любые локальные переменные и вложенные
функции, необходимые для реализации его логики

Компонент должен возвращать в качестве результата объектную структуру, представляющую
содержимое компонента, которое должно быть выведено на странице. Эта объектная структура описывается с применением языка **JSX**.

```jsx
function Hello() {
  return <h1>Привет, мир!</h1>;
}
```

```jsx
const Hello = () => <h1>Привет, мир!</h1>;
```

### Разбиение содержимого компонента на фрагменты

В функции компонента можно объявить вложенные функции, возвращающие в качестве результата части содержимого компонента, и вызывать эти функции в нужных местах кода, создающего содержимое. Это позволит сделать код более
наглядным и упростить его сопровождение.

В примере языковые конструкции JavaScript, в частности условные выражения (поз. 1–3)

```jsx
import { useLoaderData } from "react-router-dom";
export default function TodoDetail() {
  const todo = useLoaderData();
  const getDoneMark = () => {
    if (todo.done)
      // ............................................ 1
      return <p className="has-text-success">Выполнено</p>;
  };
  const getDesc = () => {
    if (todo.desc)
      // ............................................ 2
      return <p>{todo.desc}</p>;
  };
  const getImage = () => {
    if (todo.image)
      // ........................................... 3
      return (
        <p>
          <img src={todo.image} />
        </p>
      );
  };

  return (
    <section>
      {getDoneMark()}
      <h1>{todo.title}</h1>
      <p>{todo.createdAt}</p>
      {getDesc()}
      {getImage()}
    </section>
  );
}
```

### Props

Функция, реализующая компонент, должна принимать единственный параметр — простой объект. <br/>
`Props` — это входные данные компонента находящиеся в одном объекте, которые он получает от родителя.

Проще говоря: `props` — это как аргументы функции, только для компонентов. `props` в React являются объектом.

#### Свойства

1. Только для чтения (immutable) <br/> Нельзя менять props внутри компонента:
   ```jsx
   props.name = "Иван"; ❌
   ```
2. Передаются сверху вниз <br/> Родитель → дочерний компонент <br/> Но родитель может передать дочернему функцию
   - Родитель → callback через props → Дочерний
   - Дочерний → вызывает callback → Родитель изменяет state

3. Могут быть любыми данными (примитивы, объекты, jsx)

#### Использование `props`

:::note
В фигурных скобках {`{}`} передаётся JavaScript-выражение, а без них — обычная строка.
:::

```jsx
function Greeting(props) {
  return <h1>Привет, {props.name}!</h1>;
}
```

```jsx
<input {...props} />
```

```jsx
<Card name="Wasd" age={20} isAdmin={true} />
```

#### Деструктуризация

```jsx
function Greeting({ name }) {
  return <h1>Привет, {name}!</h1>;
}
```

```jsx
Card({
  name: "Wasd",
  age: 20,
  isAdmin: true,
});
```

#### `Props.children`

Специальный prop — `children`, который содержит вложенный контент:

```jsx
function Card({ children }) {
  return <div className="card">{children}</div>;
}

...

<Card>
  <h2>Заголовок</h2>
  <p>Текст</p>
</Card>
```

#### Подъём состояния вверх (lifting state up)

Состояние перемещают в общий родительский компонент. Этот подход называется подъёмом состояния вверх (lifting state up).

После перемещения состояния родительский компонент становится источником данных (single source of truth), а дочерние компоненты получают необходимые значения через `props`. Чтобы дочерний компонент мог изменить состояние, родитель передаёт ему функцию обратного вызова (callback function) также через `props`.

#### Обратная передача данных от дочернего компонента к родительскому

Дочерний компонент сообщил родителю о каком-либо событии или передал ему данные. Для этого используется функция обратного вызова (callback function).

Родительский компонент создаёт функцию и передаёт её дочернему компоненту через props. Дочерний компонент вызывает эту функцию в нужный момент и передаёт необходимые данные в качестве аргументов.

```
Родитель
  ↓ props (callback-функция)
Дочерний компонент
  ↓ вызов callback с данными
Родитель получает данные и изменяет состояние
```

```jsx
function Parent() {
  const [message, setMessage] = useState("");
  const handleMessage = (text) => {
    setMessage(text);
  };
  return (
    <>
      <Child onSendMessage={handleMessage} />
      <p>{message}</p>
    </>
  );
}

function Child({ onSendMessage }) {
  return (
    <button onClick={() => onSendMessage("Привет от дочернего компонента")}>
      Отправить сообщение
    </button>
  );
}
```

## Class Components

:::danger[Важно]
Имя компонента должно начинаться с большой буквы (это обязательно!)

Если имя компонента состоит из нескольких слов, каждое из них должно начинаться с большой буквы (TodoList, TodoDetail, TodoAdd)

Такой стиль именования сущностей в программном коде называется **PascalCase**;
:::

— это старый (но всё ещё поддерживаемый) способ создавать компоненты с помощью классов ES6.

Для создания классового компонента, нужно создать класс название которого будет название компонента, и наследовать `Component` (`React.Component`). <br/>
Создать функцию `render`

```jsx
import React, { Component } from "react";

class Welcome extends Component {
  render() {
    return <h1>Привет!</h1>;
  }
}

export default Welcome;
```

:::danger
В классовых компонентах React нельзя использовать хуки.
:::

### Состояние

В классовом компоненте состояние (state) обычно создается двумя способами.

#### Через `constructor` (классический способ)

```jsx
import React, { Component } from "react";

class Counter extends Component {
  constructor(props) {
    super(props);

    this.state = {
      count: 0,
      name: "Иван",
    };
  }

  render() {
    return (
      <div>
        <p>Счетчик: {this.state.count}</p>
        <p>Имя: {this.state.name}</p>
      </div>
    );
  }
}

export default Counter;
```

#### Через свойство класса (современный способ)

```jsx
import React, { Component } from "react";

class Counter extends Component {
  state = {
    count: 0,
    name: "Иван",
  };

  render() {
    return (
      <div>
        <p>Счетчик: {this.state.count}</p>
        <p>Имя: {this.state.name}</p>
      </div>
    );
  }
}

export default Counter;
```

#### Изменение состояния

```jsx
this.setState({
  count: this.state.count + 1,
});
```

## Жизненный цикл компонента

Жизненный цикл (время существования на странице) компонента делится на три этапа:

1. **монтирование** — первое отображение на странице сразу после создания;
2. **обновление** — повторное отображение выведенного ранее компонента. Производится после изменения какого-либо из значений, относящихся к реактивным данным (пропов, состояний и др.). Выполняется быстрее, чем монтирование;
3. **размонтирование** — удаление компонента со страницы. Производится при программном удалении компонента, переходе на другой экран в процессе навигации, переходе на другую веб-страницу или закрытии веб-обозревателя.

Компоненту можно задать действия для разных этапов его жизненного цикла: при создании (монтировании), обновлении и удалении (размонтировании). Для этого используются специальные функции — [хуки](/docs/frontend/frameworks/react/hooks). Например, с их помощью можно управлять состоянием или выполнять побочные эффекты.

## Рендеринг компонента

Рендерингом называется вывод компонента на страницу. Рендеринг выполняет сам
React, основываясь на содержимом компонента, которое описывается объектной
структурой и возвращается функцией, реализующей компонент.

### Первоначальный

— выполняется при монтировании (первом отображении) компонента на странице.

При первоначальном рендеринге React, помимо вывода содержимого компонента на странице, также создает в памяти его компактное представление — виртуальную DOM. Она потребуется при последующих обновлениях компонента, чтобы выяснить, какие элементы, входящие в состав содержимого компонента, требуется изменить, а какие — нет;

### Повторный

— выполняется при обновлении (повторном отображении) компонента.

При повторном рендеринге React сравнивает новое содержимое компонента с текущим, которое описано виртуальной DOM, сохраненной в памяти ранее, при первоначальном рендеринге. При этом обновляются только изменившиеся элементы содержимого, за счет чего обновление компонента производится максимально быстро.

## Условный рендеринг

Если компонент должен выводить содержимое только в случае выполнения заданного условия, предотвратить его вывод, если условие не выполнено, можно, вернув из функции, реализующей компонент, какое-либо «пустое» значение: `""` (пустую строку), `null` или `undefined`.

## Управляемый компонент (Controlled Component) `useState`

В управляемом компоненте значение поля хранится в состоянии React (`state`). React полностью контролирует содержимое поля.

```jsx
import { useState } from "react";

function Form() {
  const [name, setName] = useState("");

  return (
    <input type="text" value={name} onChange={(e) => setName(e.target.value)} />
  );
}
```

## Неуправляемый компонент (Uncontrolled Component) `useRef`

В неуправляемом компоненте значение хранится в самом DOM, а React его не контролирует. Чтобы получить значение, используют `ref`.
