TCP (Transmission Control Protocol) — это сетевой протокол, который обеспечивает надёжную передачу данных между устройствами через интернет или локальную сеть.

<Callout type="success">
  TCP следит за тем, чтобы данные дошли до получателя полностью, в правильном
  порядке и без потерь.
</Callout>

<Callout type="warn">
  Сегмент отправленный позже, может придти раньше или вообще не дойти! <br />
  Гарантия работает испольуя порядковый номер и номер подтверждения!
</Callout>

<hr />

### Заголовок TCP

Минимальный размер — 20 байт, максимальный — 60 байт.

```

Порт        | Порт          | Порядковый номер  | Номер подтверждения           | Длина заголовка   | Флаги     | Размер окна   | Контрольная сумма | Указатель срочных данных  | Опции         |
отправителя | получателя    | байтов            | байта (след. подтверждения)   |                   |           |               |                   |                           | и заполнение  |
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
55315       | 80            | 256               | 256                           | 20                | 000000000 | 256           |                   |                           |               |                                                                                                                                       |
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
В битах: 16 | 16            | 32                | 32                            | 32                                            | 16                | 16                        | до 40 байт    |

```

#### Основные TCP-флаги

| Флаг | Бит   | Назначение                                                               |
| ---- | ----- | ------------------------------------------------------------------------ |
| SYN  | 1     | Установка соединения и синхронизация порядковых номеров                  |
| ACK  | 2     | Подтверждение получения данных                                           |
| FIN  | 4     | Корректное завершение соединения                                         |
| RST  | 8     | Сброс соединения                                                         |
| PSH  | 16    | Просьба передать данные приложению без лишнего ожидания                  |
| URG  | 32    | Указывает, что поле Urgent Pointer содержит актуальную информацию        |
| ECE  | 64    | Используется для сигнализации о поддержке ECN и уведомления о перегрузке |
| CWR  | 128   | Указывает, что отправитель отреагировал на уведомление о перегрузке      |
| NS   | 256\* | Дополнительный флаг защиты ECN                                           |

<hr />

### Как работает TCP

TCP обеспечивает надёжную передачу данных с помощью порядковых номеров (Sequence Number) и номеров подтверждения (Acknowledgment Number). Получатель сообщает отправителю, какие данные уже получил, а какие ещё ожидает.

<Callout type="warn">
  Сегмент отправленный позже, может придти раньше или вообще не дойти! <br />
  Гарантия доставки: порядковый номер и номер подтверждения!
</Callout>

1. Приходит сообщение с прикладного уровня.
2. Разделение данных на сегменты и каждому такому сегменту добавляется `заголовок TCP `
3. Передача получателю
4. Проверка и сборка

#### Как TCP восстанавливает потерянные данные?

1. Отправитель не получает подтверждение нужных данных или получает повторяющиеся ACK.
2. TCP определяет, что сегмент, вероятно, потерян.
3. Отправитель повторно передаёт недостающие данные — это называется ретрансляцией (retransmission).
4. Получатель принимает недостающие байты и подтверждает новый непрерывный диапазон полученных данных.

#### Как TCP гарантирует доставку

| Механизм          | Зачем нужен                                                     |
| ----------------- | --------------------------------------------------------------- |
| SEQ               | Позволяет определить порядок байтов                             |
| ACK               | Подтверждает полученные байты                                   |
| Таймер            | повторной передачи Помогает обнаружить отсутствие подтверждения |
| Retransmission    | Повторно отправляет потерянные данные                           |
| Контрольная сумма | Обнаруживает повреждение сегмента                               |
| Буферизация       | Позволяет собрать данные в правильном порядке                   |

<Callout title="Важный нюанс">
  TCP гарантирует надёжную доставку упорядоченного потока байтов приложению при
  условии, что соединение успешно завершается. Он не может гарантировать
  доставку, если связь окончательно оборвалась: в таком случае соединение
  завершается ошибкой.
</Callout>

## TCP/IP

— это набор правил (протоколов), которые позволяют компьютерам, телефонам, серверам и другим устройствам обмениваться данными через интернет и локальные сети.

TCP/IP расшифровывается как:

- TCP (Transmission Control Protocol) — протокол управления передачей данных.
- IP (Internet Protocol) — интернет-протокол, отвечающий за адресацию и доставку пакетов данных.

<hr />

### Где используется TCP/IP

Практически везде, где устройства общаются по сети:

- Открытие сайтов.
- Отправка электронной почты.
- Общение в мессенджерах.
- Онлайн-игры.
- Обмен данными между серверами.

<hr />

### Уровни (модель) TCP/IP

Модель TCP/IP состоит из 4 уровней, каждый из которых выполняет свою задачу при передаче данных по сети. Вместе они обеспечивают работу интернета.

<hr />

#### 4.Прикладной уровень

Обеспечивает работу сетевых приложений и обмен данными между ними. <br/>
Обеспечивает сетевые службы для приложений и определяет правила обмена данными между ними.

Объединяет 3 уровная модели [OSI](../webs/osi-model.mdx): Прикладной, Представления, Сеансовый.

<Callout>Протоколы: HTTP/HTTPS, DNS, SMTP, SSH, DHCP</Callout>

Прикладной уровень решает такие проблемы:

- Предоставление сетевых служб приложениям — обеспечение доступа к веб-сайтам, электронной почте, передаче файлов, удалённому доступу и другим сетевым ресурсам.
- Формирование правил обмена данными — определение структуры запросов и ответов, допустимых команд и порядка взаимодействия приложений. Например, HTTP определяет взаимодействие веб-клиента и сервера.

Уровень представления решает такие проблемы:

- Кодирование и преобразование форматов — преобразование данных в согласованный формат. Например, UTF-8 для текста, JSON для структурированных данных.
- Шифрование и расшифрование — защита данных от прочтения посторонними. Например, TLS обеспечивает шифрование при передаче данных по HTTPS.
- Сжатие и распаковка — уменьшение объёма передаваемых данных. Например, сжатие изображений или данных с помощью gzip.

Сеансовый уровень решает такие проблемы:

- Установление, поддержание и завершение сеанса — организация взаимодействия приложений, включая восстановление сеанса в системах, которые это поддерживают.
- Восстановление после сбоев — возможность возобновить взаимодействие с контрольной точки, если протокол и приложение поддерживают такую функцию.
- Синхронизация потоков поступающих данных — установка контрольных точек, позволяющих продолжить передачу или обработку данных после сбоя. Синхронизация аудио- и видеопотоков может выполняться другими протоколами и механизмами.
- Контроль одновременного выполнения одной и той же задачи разными поступающими сетевыми запросами
- Управление диалогом — координация обмена данными, например определение того, какая сторона может передавать данные в конкретный момент.

<hr />

#### 3.Транспортный уровень

Передаёт данные между приложениями, используя [порты](../webs/port.mdx). Может обеспечивать надёжность передачи.

<Callout>Протоколы: TCP, UDP</Callout>

<hr />

#### 2.Межсетевой уровень

Отвечает за IP-адресацию и маршрутизацию пакетов между сетями.

<Callout>Протоколы: IPv4, IPv6, ICMP</Callout>

<hr />

#### 1.Уровень сетевого доступа

Передаёт данные непосредственно по физической или беспроводной сети.

Совмещает 2 уровная модели [OSI](../webs/osi-model.mdx): Канальный, Физический.

<Callout>Технологии: Ethernet, Wi-Fi, PPP</Callout>

<hr />

### Как работает TCP/IP

1. Твоё устройство <br/>
   Сообщение разбивается на части
2. TCP <br/>
   Контролирует передачу, порядок и повторную отправку потерянных данных
3. IP <br/>
   Помогает пакетам найти путь к нужному устройству по IP-адресу
4. Устройство получателя <br/>
   Данные собираются в правильном порядке

<details>
  <summary>Пример аналогия</summary>

Вспомните, как работает наша обычная почта.

1. На листке пишете письмо.
2. Кладете его в конверт, заклеиваете.
3. На обратной стороне конверта пишете адреса отправителя и получателя.
4. Относите в ближайшее почтовое отделение.
5. Письмо проходит через цепочку почтовых отделений до ближайшего почтового отделения получателя.
6. Почтальоном доставляется до по указанному адресу получателя и опускается в его почтовый ящик (с номером его квартиры) или вручается лично.
7. Когда получатель письма захочет вам ответить, то он в своем ответном письме поменяет местами адреса получателя и отправителя, и письмо отправиться к вам по той же цепочке, но в обратном направлении.

На конверте письма будет написано примерно следующее:

```
Адрес отправителя:
От кого: Иванов Иван Иванович
Откуда: Ивантеевка, ул. Большая , д. 8, кв. 25

Адрес получателя:
Кому: Петров Петр Петрович
Куда: Москва, Усачевский переулок, д. 105, кв. 110
```

Каждый компьютер (он же: **узел**, **хост**) в рамках сети Интернет тоже имеет уникальный адрес,
который называется [IP-адрес (Internet Protocol Address)](../webs/ip-address.mdx), например: `195.34.32.116`. IP адрес состоит из четырех десятичных чисел (от 0 до 255),
разделенных точкой. Но знать только IP адрес компьютера еще недостаточно,
т.к. в конечном счете **обмениваются информацией не компьютеры сами по себе, а приложения, работающие на них**.
А на компьютере может одновременно работать сразу несколько приложений (например почтовый сервер, веб-сервер и пр.).
Для доставки обычного бумажного письма недостаточно знать только адрес дома — необходимо еще знать номер квартиры.
Также и каждое программное приложение имеет подобный номер, именуемый номером [порта](../webs/port.mdx).
Большинство серверных приложений имеют стандартные номера, например: почтовый сервис привязан к порту с номером `25` (еще говорят: «слушает» порт, принимает на него сообщения), веб-сервис привязан к порту `80`, FTP - к порту `21` и так далее.

Таким образом имеем следующую практически полную аналогию с нашим обычным почтовым адресом:

```
"адрес дома" = "IP компьютера"
"номер квартиры" = "номер порта"
```

В компьютерных сетях, работающих по протоколам TCP/IP, аналогом бумажного письма в конверте является пакет,
который содержит собственно передаваемые данные и адресную информацию — адрес отправителя и адрес получателя, например:

```
Адрес отправителя (Source address):
IP: 82.146.49.55
Port: 2049

Адрес получателя (Destination address):
IP: 195.34.32.116
Port: 53

Данные пакета:
...
```

<Callout>
  Обратите внимание, комбинация: "IP адрес и номер порта" - называется "сокет".
  <br />В сетевом программировании комбинацию IP-адрес + номер порта часто
  называют сетевым сокетом (socket address) в бытовом или упрощённом объяснении.
</Callout>

В нашем примере мы с сокета `82.146.49.55:2049` посылаем пакет на сокет `195.34.32.116:53`,
т.е. пакет пойдет на компьютер, имеющий IP адрес `195.34.32.116`, на порт `53`. А порту `53` соответствует сервер распознавания имен (DNS-сервер), который примет этот пакет.
Зная адрес отправителя, этот сервер сможет после обработки нашего запроса сформировать ответный пакет,
который пойдет в обратном направлении на сокет отправителя `82.146.49.55:2049`, который для DNS сервера будет являться сокетом получателя.

Как правило взаимодействие осуществляется по схеме «клиент-сервер»: "клиент" запрашивает какую-либо информацию (например страницу сайта),
сервер принимает запрос, обрабатывает его и посылает результат.
Номера портов серверных приложений общеизвестны, например: почтовый SMTP сервер «слушает» 25-й порт,
POP3 сервер, обеспечивающий чтение почты из ваших почтовых ящиков «слушает» 110-порт, веб-сервер - 80-й порт и пр.

Номера портов на клиенте не фиксированные как у сервера, а назначаются операционной системой динамически.
Фиксированные серверные порты как правило имеют номера до `1024` (но есть исключения), а клиентские начинаются после `1024`.

<details>
  <summary>DNS</summary>

Однако человеку запоминать цифровые IP адреса трудно - куда удобнее работать с
буквенными именами. Ведь намного легче запомнить слово, чем набор цифр. Так и
сделано - любой цифровой IP адрес можно связать с буквенно-цифровым именем. В
результате например вместо `82.146.49.55` можно использовать имя
`www.ofnet.ru`. А преобразованием доменного имени в цифровой IP адрес
занимается сервис доменных имен — [DNS (Domain Name System)](../webs/dns.mdx).

    Рассмотрим подробнее, как это работает. Ваш провайдер явно (на бумажке, для ручной настройки соединения) или неявно (через автоматическую настройку соединения) предоставляет вам IP адрес сервера имен (DNS).
    На компьютере с этим IP адресом работает приложение (сервер имен), которое знает все доменные имена в Интернете и соответствующие им цифровые IP адреса.
    DNS-сервер «слушает» 53-й порт, принимает на него запросы и выдает ответы, например:

    ```
    Запрос от нашего компьютера: "Какой IP адрес соответствует имени www.ofnet.ru?"
    Ответ сервера: "82.146.49.55."
    ```

    Теперь рассмотрим, что происходит, когда в своем браузере вы набираете доменное имя (URL) этого сайта (`www.ofnet.ru`) и, нажав `<enter>`, в ответ от веб-сервера получаете страницу этого сайта.

    Например:

    ```
    IP адрес нашего компьютера: 91.76.65.216
    Браузер: Internet Explorer (IE),
    DNS сервер (стрима): 195.34.32.116 (у вас может быть другой),
    Страница, которую мы хотим открыть: www.ofnet.ru.
    ```

    Набираем в адресной строке браузера доменное имя `www.ofnet.ru` и жмем `<enter>`.
    Далее операционная система производит примерно следующие действия:

    Отправляется запрос (точнее пакет с запросом) DNS серверу на сокет `195.34.32.116:53`. Как было рассмотренно выше, порт `53` соответствует DNS-серверу - приложению,  занимающемуся распознаванием имен. А DNS-сервер, обработав наш запрос, возвращает IP-адрес, который соответствует введенному имени.

    ```
    - Какой IP адрес соответствует имени www.ofnet.ru?
    - 82.146.49.55.
    ```

    Далее наш компьютер устанавливает соединение с портом `80` компьютера `82.146.49.55` и посылает запрос (пакет с запросом) на получение страницы `www.ofnet.ru`.
    `80`-й порт соответствует веб-серверу. В адресной строке браузера `80`-й порт как правило не пишется, т.к. используется по умолчанию, но его можно и явно указать после двоеточия - `http://www.ofnet.ru:80`.
