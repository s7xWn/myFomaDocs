---
title: Архитектурный стиль веб-API
---

— это набор принципов и правил, определяющих, как клиент и сервер взаимодействуют друг с другом, как организованы ресурсы, запросы, ответы и обмен данными.

| Стиль                               | Краткое описание                                 | Когда используется                       |
| ----------------------------------- | ------------------------------------------------ | ---------------------------------------- |
| **REST**                            | Работа с ресурсами через HTTP, stateless         | Большинство веб-сервисов                 |
| **RPC (Remote Procedure Call)**     | Вызов удаленной функции как локальной            | Внутренние сервисы                       |
| **gRPC**                            | Современный RPC поверх HTTP/2 и Protocol Buffers | Микросервисы, высокая производительность |
| **SOAP**                            | XML-протокол со строгим контрактом               | Банки, государственные системы           |
| **GraphQL**                         | Клиент сам определяет необходимые данные         | Сложные frontend-приложения              |
| **WebSocket**                       | Постоянное двустороннее соединение               | Чаты, игры, биржи                        |
| **Server-Sent Events (SSE)**        | Сервер отправляет события клиенту                | Уведомления, мониторинг                  |
| **Event-Driven Architecture (EDA)** | Компоненты взаимодействуют через события         | Асинхронные системы                      |
| **Message Queue Architecture**      | Обмен сообщениями через брокер                   | Масштабируемые системы                   |
