## Rules (`/init`)

| [Rules for Cursor](https://cursor.directory) |
| -------------------------------------------- |

```
/init
```

Анализирует проект и создаёт/обновляет `AGENTS.md` с рекомендациями по структуре проекта, командам сборки, тестам, архитектуре и т. п.

**Rules** — это набор постоянных инструкций для AI-агента: они говорят ему, как работать именно с твоим проектом.

> По смыслу это аналог Rules в Cursor или `CLAUDE.md` в Claude Code.

Главный механизм — файл `AGENTS.md`

После этого, когда OpenCode работает в этом проекте, эти инструкции попадают в контекст модели и влияют на её действия.

<details>
  <summary>Пример</summary>

В `AGENTS.md` можно написать:

```md
# Project Rules

- Используй TypeScript, не JavaScript.
- Для форматирования запускай `bun run format`.
- После изменения кода запускай `bun test`.
- Не изменяй файлы в `generated/`.
- Для API используй существующий слой `src/api/`.
- Не добавляй зависимости без необходимости.
```

</details>

<hr />

### Project Rules

Правила конкретного проекта. Их имеет смысл положить в Git, чтобы ими пользовалась вся команда.

```
./AGENTS.md
```

<hr />

### Global Rules

Применяются ко всем твоим проектам.

```
~/.config/opencode/AGENTS.md
```

Например:

```
- Всегда отвечай на русском.
- Перед изменениями объясняй план.
- После изменений запускай тесты.
```

<hr />

### `opencode.json` → `instructions`

Необязательно складывать всё в один огромный `AGENTS.md`.Можно подключить несколько файлов:

```
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "CONTRIBUTING.md",
    "docs/development-standards.md",
    ".cursor/rules/*.md"
  ]
}
```

## Agent

### Switch model <br/> (`ctrl + x` -> `m`) (`/models`)

Переключает LLM, которая будет обслуживать текущую сессию.

<details>
  <summary>Пример</summary>

Допустим, ты начал работу с Claude:

> Проанализируй этот проект и исправь авторизацию

А потом нажал **Switch Model** → GPT-5.6.

**OpenCode** не забывает проект и предыдущий контекст — следующие сообщения в этой сессии будут отправляться уже GPT-5.6.

<Callout>
Это особенно полезно, если ты хочешь, например:

Claude → для анализа → GPT → для реализации → другая модель → для быстрого ревью.

</Callout>

</details>

### Toggle MCPs <br/> (`/mcps`)

| [MCP Market / Top MCP](https://mcpmarket.com/leaderboards) |
| ---------------------------------------------------------- |

MCP — это Model Context Protocol, стандарт, который позволяет OpenCode подключать к AI внешние инструменты и сервисы.

Например, без MCP OpenCode умеет работать с кодом и встроенными инструментами. Через MCP ему можно дать инструменты для:

- поиска и чтения документации;
- запросов к базе данных;
- работы с GitHub;
- взаимодействия с внешними API;
- доступа к определённым файлам;
- управления браузером через Playwright;
- работы со специализированными сервисами.

OpenCode после подключения MCP-сервера обнаруживает его инструменты и может использовать их вместе со своими встроенными инструментами.

<details>
  <summary>Как это выглядит на практике</summary>

Context7 — MCP-сервер для документации.

Тогда вместо ситуации:

```
Ты: Как использовать API React Router?

AI: Я знаю примерно как...
```

может быть:

```
Ты: Как использовать API React Router?

OpenCode → MCP Context7 → получает актуальную документацию
        ↓
      AI → пишет код на основе документации
```

</details>

OpenCode выступает MCP-клиентом, а отдельные MCP-серверы предоставляют ему инструменты.

Сервер может быть локальным — OpenCode запускает программу на твоём компьютере, либо удалённым — подключается к серверу по сети. В актуальной документации OpenCode это настраивается через `mcp.servers`.

## Provider

### Connect Provider <br/> (`/connect`)

**Connect Provider** в OpenCode — это подключение провайдера моделей, то есть сервиса, через который OpenCode получает доступ к LLM.

Обычно процесс такой: <br/>

> Connect Provider → выбрать провайдера → ввести API key / пройти авторизацию → провайдер становится доступен для выбора моделей.

## Prompt

### Skills <br/> (`/skills`)

| [MCP Market / Top skills](https://mcpmarket.com/tools/skills/leaderboard) | [Skills.sh](https://www.skills.sh) |
| ------------------------------------------------------------------------- | ---------------------------------- |

**Skills** (скиллы) — это набор инструкций, которые учат AI-агента как выполнять определённый тип задач.

Проще всего представить skill как мини-инструкцию или методичку для агента.

<Callout type="success">

**OpenCode** прямо поддерживает **Claude Code Skills**.

</Callout>

<details>
  <summary>Пример</summary>

Например, без skill ты говоришь:

> Сделай code review этого PR

А со skill `code-review` агенту заранее объяснено:

1. Сначала посмотреть изменённые файлы.
2. Проверить безопасность.
3. Проверить обработку ошибок.
4. Проверить тесты.
5. Не придираться к стилю без причины.
6. Результат оформить в определённом формате.

Тогда тебе достаточно написать:

> Сделай code review.

</details>

Обычно skill — это папка с файлом:

```
skills/
└── code-review/
    ├── SKILL.md
    ├── checklist.md
    └── examples.md
```

<details>
  <summary>Пример реализации этого скилла</summary>

Главный файл:

```mdx
---
name: code-review
description: Review code for bugs, security issues and maintainability
---

# Code Review

When reviewing code:

1. Look for correctness issues.
2. Check security implications.
3. Check error handling.
4. Check tests.
5. Report only actionable findings.
```

AI загружает эту инструкцию, когда понимает, что задача относится к `code-review`.

</details>

#### Чем Skill отличается от обычного промпта?

**Skill** позволяет вынести повторяющиеся знания и рабочие процессы из контекста разговора.

Промпт:

> Проверь этот код на безопасность

Skill:

> Вот наша стандартная методология проверки безопасности. Всегда проверяй A, B, C и D, используй такие-то инструменты, результат оформляй так-то».
