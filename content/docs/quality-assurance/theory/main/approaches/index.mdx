---
title: Подходы к тестированию (Testing Approaches)
---

— это способы, которыми тестировщик организует проверку программного продукта, чтобы найти дефекты и убедиться, что система соответствует требованиям.

> Подход отвечает на вопрос «как именно мы будем тестировать?»

Основные подходы:

1. **Ручное тестирование (Manual Testing)** <br/>
   Тестировщик выполняет проверки самостоятельно, без автоматизации. <br/>
   _Например: открыть сайт → заполнить форму → нажать «Войти» → проверить результат._
2. **Автоматизированное тестирование (Automation Testing)** <br/>
   Проверки выполняются с помощью программ и тестовых фреймворков. <br/>
   _Например, автотест сам вводит логин и пароль и проверяет, что пользователь успешно авторизовался._
3. **[Black Box Testing («чёрный ящик»)](./testing-box-method.mdx#чёрный-ящик-black-box-testing)** <br/>
   Тестировщик не знает внутреннего устройства программы и проверяет только входные данные и результаты. <br/>
   _Например: вводим 100 + 200 и проверяем, что калькулятор показывает 300._
4. **[White Box Testing («белый ящик»)](./testing-box-method.mdx#белый-ящик-white-box-testing)** <br/>
   Тестирование основано на знании внутреннего кода и логики приложения. Обычно этим больше занимаются разработчики и специалисты по automation/SDET.
5. **[Gray Box Testing («серый ящик»)](./testing-box-method.mdx#серый-ящик-grey-box-testing)** <br/>
   Комбинация двух подходов: тестировщик знает некоторую внутреннюю информацию о системе, но тестирует её преимущественно как пользователь.
6. **Позитивное тестирование** <br/>
   Проверяем корректные сценарии. <br/>
   _Например: вводим правильный email и пароль → пользователь входит в аккаунт._
7. **Негативное тестирование** <br/>
   Проверяем, как система реагирует на неправильные или неожиданные данные. <br/>
   _Например: неправильный пароль → появляется сообщение об ошибке._
8. **Risk-based Testing** <br/>
   Сначала тестируем функциональность, которая несёт наибольший риск для бизнеса или пользователей. Например, в интернет-банке приоритетом будут платежи и переводы, а не изменение цвета кнопки.
