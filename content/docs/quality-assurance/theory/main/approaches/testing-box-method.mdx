---
title: Тестирование по знанию системы (методом «ящика»)
---

— это подход к тестированию программного обеспечения, при котором проверяется программа с определённой точки зрения, зависящей от того, доступна ли внутренняя структура кода.

1. Чёрный ящик (Black Box Testing)
2. Белый ящик (White Box Testing)
3. Серый ящик (Grey Box Testing)

| Вид тестирования | Знание кода | Основная цель                                    |
| ---------------- | ----------- | ------------------------------------------------ |
| Чёрный ящик      | Нет         | Проверка функций и требований                    |
| Белый ящик       | Да          | Проверка логики и структуры кода                 |
| Серый ящик       | Частично    | Проверка системы с учётом внутреннего устройства |

<hr />

## Чёрный ящик (Black Box Testing)

Тестировщик не знает внутреннего устройства программы. Проверяется только:

- входные данные;
- получаемые результаты;
- соответствие требованиям.

<hr />

## Белый ящик (White Box Testing)

Тестировщик знает внутреннюю структуру программы:

- исходный код;
- алгоритмы;
- ветвления;
- циклы.

<hr />

## Серый ящик (Grey Box Testing)

— это подход, который объединяет элементы тестирования «чёрного» и «белого» ящика. При таком методе тестировщик имеет ограниченные знания о внутреннем устройстве системы: например, знает особенности архитектуры, базы данных или алгоритмов, но не анализирует весь исходный код программы.

Главная цель серого ящика — проверить, насколько правильно система работает с учётом некоторой информации о её внутренней структуре. Тесты выполняются в основном через внешние интерфейсы, но при их создании учитываются внутренние особенности программы.
