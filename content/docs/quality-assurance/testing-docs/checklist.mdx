## Чек-лист (Checklist)

— это структурированный список проверок, который содержит набор пунктов, по которым тестировщик должен пройтись, чтобы убедиться, что определённые требования или функции системы проверены.

Используются, когда не нужна подробная инструкция.

Применяются в:

- Регрессионное тестирование — быстро проверить, что старый функционал не сломался после изменений.
- Smoke-тестирование — убедиться, что приложение вообще работает.
- Приёмочное тестирование — проверить соответствие требованиям заказчика.
- Мобильное и веб-тестирование — проверка стандартных сценариев.
- Повторяющиеся проверки — например, перед каждым релизом.

### Пример

Чек-лист: Регистрация пользователя

- ☐ Поле «Имя» отображается
- ☐ Поле «Email» отображается
- ☐ Поле «Пароль» отображается
- ☐ Нельзя отправить форму с пустыми обязательными полями
- ☐ Проверяется корректность email-адреса
- ☐ Пароль соответствует требованиям безопасности
- ☐ После успешной регистрации пользователь получает сообщение об успехе
- ☐ Пользователь может войти с созданными данными

### Отличие от тест-кейса

| Чек-лист                                  | Тест-кейс                                  |
| ----------------------------------------- | ------------------------------------------ |
| Краткий список проверок                   | Подробная инструкция проверки              |
| Содержит только пункты проверки           | Содержит шаги, данные, ожидаемый результат |
| Быстрее создавать и выполнять             | Требует больше времени на подготовку       |
| Подходит для регрессии и быстрых проверок | Подходит для детального тестирования       |

Чек-лист:

- ☐ Проверить авторизацию с неверным паролем

Тест-кейс:

1. Открыть страницу входа
2. Ввести существующий логин
3. Ввести неправильный пароль
4. Нажать кнопку "Войти"
5. Ожидаемый результат: появляется сообщение "Неверный пароль"
