## Баг-репорт (Bug Report)

— это документ или запись в системе отслеживания задач, в которой QA подробно описывает найденную ошибку, чтобы разработчики могли воспроизвести и исправить её.

Главная цель баг-репорта — ответить на три вопроса:

1. Что произошло?
2. Как это повторить?
3. Что должно было произойти вместо этого?

### Severity и Priority

**Severity** (серьёзность) — насколько сильно ошибка влияет на работу приложения.

Примерная классификация:

- Blocker — приложение или ключевой функционал полностью не работает.
- Critical — потеря данных, невозможность использовать основную функцию.
- Major — важная функция работает некорректно, но есть обходной путь или затронута не вся система.
- Minor — небольшие функциональные ошибки.
- Trivial — опечатки, проблемы с отображением, косметические дефекты.

**Priority** (приоритет) — насколько быстро ошибку нужно исправить с точки зрения бизнеса или команды.

Примерные типы:

1. Самый важный
2. Средний
3. Низкий

Например:

- Высокая серьёзность и высокий приоритет: невозможно оформить заказ в интернет-магазине.
- Низкая серьёзность и высокий приоритет: неверная цена на главной странице (функциональность не сломана, но ошибка критична для бизнеса).
- Высокая серьёзность и низкий приоритет: редко используемая функция перестала работать.

### Структура (примерная)

| Поле                            | Описание                                                       |
| ------------------------------- | -------------------------------------------------------------- |
| **ID**                          | Уникальный номер ошибки (обычно назначается автоматически).    |
| **Title (Заголовок)**           | Краткое описание проблемы.                                     |
| **Environment (Окружение)**     | Где обнаружен баг: устройство, ОС, браузер, версия приложения. |
| **Preconditions (Предусловия)** | Что должно быть выполнено до начала проверки.                  |
| **Steps to Reproduce**          | Пошаговая инструкция воспроизведения.                          |
| **Actual Result**               | Что произошло на самом деле.                                   |
| **Expected Result**             | Что должно было произойти.                                     |
| **Severity**                    | Насколько серьёзна ошибка.                                     |
| **Priority**                    | Насколько срочно её нужно исправить.                           |
| **Attachments**                 | Скриншоты, видео, логи, дампы и т.д.                           |
