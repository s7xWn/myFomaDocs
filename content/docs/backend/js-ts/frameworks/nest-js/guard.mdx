title: "Guard"

Guard в NestJS — это специальный класс, который решает, можно ли пропустить запрос к определённому endpoint (маршруту).
Чаще всего Guard используют для авторизации, проверки прав доступа и ролей пользователя.

Например, Guard может проверить, авторизован ли пользователь, прежде чем разрешить ему получить доступ к `/admin`.

```bash
nest g guard auth
```

```bash
nest g guard auth/guards/auth --flat
```

<details>
  <summary>Пример созданного кода</summary>

```ts
import { Injectable, CanActivate, ExecutionContext } from "@nestjs/common";

@Injectable()
export class AuthGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();

    return Boolean(request.user);
  }
}
```

Разберём основные элементы:

- `@Injectable()` — позволяет NestJS управлять классом через Dependency Injection.
- `CanActivate` — интерфейс, определяющий контракт Guard.
- `ExecutionContext` — предоставляет информацию о текущем запросе и обработчике.
- `canActivate()` — метод, который возвращает `true` или `false` либо асинхронный результат.

</details>

## Работа Guard

```
    HTTP-запрос
    [GET /admin]
        ||
        \/
    Guard
    [Проверяет токен, роль или права доступа]
        /                           \
    true                            false
[Запрос проходит дальше]     [NestJS возвращает 403 Forbidden]
```

### Guard vs Middleware vs Interceptor

| Механизм    | Для чего нужен                                                           |
| ----------- | ------------------------------------------------------------------------ |
| Middleware  | Обработка запроса до Guard, например логирование или добавление данных   |
| Guard       | Решает, разрешён ли доступ к маршруту                                    |
| Pipe        | Проверяет и преобразует входные данные                                   |
| Interceptor | Выполняет логику до и после обработчика, например логирование результата |
| Exception   | Filter Обрабатывает исключения и формирует HTTP-ответ                    |

## Примеры Guard'ов

### `roles.guard.ts`

```ts
import {
  CanActivate,
  ExecutionContext,
  ForbiddenException,
  Injectable,
} from "@nestjs/common";
import { Reflector } from "@nestjs/core";
import { UserRole } from "@prisma/__generated__/enums.js";
import { ROLES_KEY } from "../decorators/roles.decorator.js";

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}
  public async canActivate(context: ExecutionContext): Promise<boolean> {
    const roles = this.reflector.getAllAndOverride<UserRole[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    const request = context.switchToHttp().getRequest();

    if (!roles) return true;
    if (!roles.includes(request.user.role)) {
      throw new ForbiddenException("Недостаточно прав");
    }
    return true;
  }
}
```

### `auth.guard.ts`

```ts
import {
  CanActivate,
  ExecutionContext,
  Injectable,
  UnauthorizedException,
} from "@nestjs/common";

import { UserService } from "@/user/user.service.js";

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private readonly userService: UserService) {}
  public async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();

    if (typeof request.session.userId === "undefined") {
      throw new UnauthorizedException("Пользователь не авторизован");
    }
    const user = await this.userService.findById(request.session.userId);
    request.user = user;

    return true;
  }
}
```
