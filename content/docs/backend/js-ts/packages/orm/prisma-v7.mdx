это ORM (Object-Relational Mapper) для Node.js и TypeScript, который позволяет удобно работать с базой данных из JavaScript/TypeScript-кода.

<hr />

## Основные части

- Prisma Schema — описываешь модели базы данных в специальном файле.
- Prisma Client — автоматически генерируемый TypeScript-клиент для запросов к БД.
- Prisma Migrate — инструмент для создания и применения миграций.
- Prisma Studio — веб-интерфейс для просмотра и редактирования данных.

<hr />

## Какие базы поддерживает

- PostgreSQL
- MySQL
- SQLite
- SQL Server
- CockroachDB
- MongoDB

## Модель

Создание модели:

```prisma
model Name{

}
```

### Поле (столбец)

```prisma
rowName Type?
```

- `rowName` — поле (столбец) этой модели
- [`Type`](#типы-данных) — тип поля (`Int`, `String`) — это типы данных Prisma, а не произвольные названия переменных БД.
- `?` - делает поле опциональным

#### `@id`

Означает: это поле является уникальным идентификатором записи (primary key).

#### `@default(...)`

Означает: если значение не указали, база/Prisma подставит значение автоматически.

#### `@map(...)`

`@map` в Prisma используется, чтобы связать имя поля в Prisma с другим именем столбца в базе данных.

```prisma
model ModelName {
  rowName String @map("row_name")
}
```

```
Prisma              База данных
─────────────       ─────────────
rowName    →        row_name
```

#### `@@map`

`@@map` применяется к моделям

```prisma
model User {
  id Int @id

  @@map("users")
}
```

### Свзяь между моделями

```prisma
model User {
  posts Post[]
}

model Post {
  authorId Int
  author   User @relation(fields: [authorId], references: [id])
}
```

- `User.posts` — список постов пользователя.
- `Post.author` — пользователь, которому принадлежит пост.
- `Post.authorId` — внешний ключ.
- `fields: [authorId]` говорит Prisma, какое поле является FK.
- `references: [id]` говорит, на какое поле `User` он ссылается.

## ENUM

<Callout type="warn">`ENUM` для **SQLite** не поддерживаются нативно</Callout>

```prisma
enum NameEnum{
  first
  second
}
```

Использование:

```prisma
model Name{
  rowName NameEnum;
}
```

## Команды

| Задача                                | Команда                                  |
| ------------------------------------- | ---------------------------------------- |
| 🚀 Новый проект                       | `npx prisma init`                        |
| 🔄 Обновить Client                    | `npx prisma generate`                    |
| 📝 Изменил `schema.prisma`            | `npx prisma migrate dev --name название` |
| 🧪 Быстро синхронизировать БД         | `npx prisma db push`                     |
| 🗄️ Получить schema из существующей БД | `npx prisma db pull`                     |
| 🌱 Запустить seed                     | `npx prisma db seed`                     |
| 👀 Посмотреть данные                  | `npx prisma studio`                      |
| 🚢 Production                         | `npx prisma migrate deploy`              |
| 🔥 Полностью пересоздать БД           | `npx prisma migrate reset`               |
| ✅ Проверить schema                   | `npx prisma validate`                    |
| ✨ Форматировать schema               | `npx prisma format`                      |

### Основные

| Команда               | Назначение                              |
| --------------------- | --------------------------------------- |
| `npx prisma init`     | Создать Prisma-проект и `schema.prisma` |
| `npx prisma generate` | Сгенерировать Prisma Client             |
| `npx prisma validate` | Проверить корректность `schema.prisma`  |
| `npx prisma format`   | Отформатировать `schema.prisma`         |
| `npx prisma studio`   | Открыть Prisma Studio                   |
| `npx prisma version`  | Показать версии Prisma и Prisma Client  |
| `npx prisma debug`    | Вывести диагностическую информацию      |

### Работа с базой

| Команда                 | Назначение                                         |
| ----------------------- | -------------------------------------------------- |
| `npx prisma db pull`    | Получить структуру БД → `schema.prisma`            |
| `npx prisma db push`    | Синхронизировать `schema.prisma` с БД без миграции |
| `npx prisma db seed`    | Запустить seed                                     |
| `npx prisma db execute` | Выполнить SQL/команды непосредственно в БД         |

### Миграции

| Команда                                  | Назначение                                 |
| ---------------------------------------- | ------------------------------------------ |
| `npx prisma migrate dev`                 | Создать и применить миграцию в development |
| `npx prisma migrate dev --name add_user` | Создать миграцию с именем                  |
| `npx prisma migrate dev --create-only`   | Создать миграцию, но не применять её       |
| `npx prisma migrate reset`               | Сбросить БД и применить миграции заново    |
| `npx prisma migrate deploy`              | Применить миграции в production/staging    |
| `npx prisma migrate status`              | Проверить состояние миграций               |
| `npx prisma migrate resolve`             | Исправить состояние migration history      |
| `npx prisma migrate diff`                | Сравнить две схемы                         |
