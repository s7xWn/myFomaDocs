## `setTimeout`

— это функция, которая планирует выполнение callback-функции после указанной задержки.

```js
setTimeout(() => {}, timeoutMs);
```

{/* prettier-ignore */}
<Callout type="warn">
  Таймер **не «останавливает** JavaScript на N миллисекунд», **не гарантирует выполнение** `callback` точно в указанное время. <br/>
  Он гарантирует только, что `callback` **не будет выполнен раньше** заданной задержки.
</Callout>

`setTimeout()` возвращает `id`

```js
const myTimer = setTimeout(() => {}, timeoutMs);
```

### Очистить таймер (`clearTimeout()`)

```js
clearTimeout(id);
```

### `unref()` / `ref()`

В Node.js у таймера есть метод `.unref()`, который говорит:

> Этот таймер не должен удерживать процесс Node.js от завершения <br/>
> `unref()` — «таймер работает, но не держи ради него Node.js-процесс живым».

Без `unref()` Node.js будет ждать заданное время, прежде чем завершить процесс:

```
программа закончила работу
        ↓
таймер ещё активен
        ↓
Node.js ждёт таймер
        ↓
через 5 секунд → процесс завершается
```

С `unref()`:

```
программа закончила работу
        ↓
таймер ещё активен, НО он unref
        ↓
Node.js больше не обязан ждать его
        ↓
процесс может завершиться
```

А обратный метод — `ref()`

## `setInterval`

— это функция, которая планирует повторное выполнение callback-функции через заданный интервал времени.

```js
setInterval(() => {}, intervalMs);
```

{/* prettier-ignore */}
<Callout type="warn">
  Интервал **не гарантирует выполнение** `callback` точно в указанное время. <br/>
  Он гарантирует только, что `callback` **не будет выполнен раньше** заданной задержки.
</Callout>

`setInterval()` возвращает `id`

```js
const myInterval = setInterval(() => {}, intervalMs);
```

### Очистить интервал (`clearInterval()`)

```js
clearInterval(id);
```

<hr />

## `setImmediate`

— это Node.js API, которое планирует выполнение callback на следующей итерации Event Loop, после завершения текущей операции.

```js
setImmediate(() => {});
```
