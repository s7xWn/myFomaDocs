title: "Pytest"
---

— это один из самых популярных фреймворков для автоматического тестирования программ на Python.
Он помогает проверять, что код работает правильно, и быстро находить ошибки после изменений.

Преимущества pytest:

- Простой синтаксис — достаточно использовать `assert`.
- Автоматический поиск тестов — файлы с именем `test_*.py` / `*_test.py` находятся автоматически.
- Автоматический поиск функций — функции с именем `test_*` находятся автоматически.
- Информативные отчеты: Если тест упал, Pytest покажет, что именно было в переменных в этот момент.
- Поддержка фикстур (fixtures) — удобная подготовка данных и окружения для тестов.
- Параметризация — можно запускать один и тот же тест с разными наборами данных.
- Большое количество плагинов — например, для измерения покрытия кода (`pytest-cov`) или запуска тестов параллельно.

Pytest рекурсивно ищет в папках файлы, чьи имена начинаются с `test_` или заканчиваются на `_test`. Внутри этих файлов он ищет функции, чьи имена начинаются с `test_`. Если тесты обернуты в классы, имя класса должно начинаться с `Test`.

## **Использование**

Можно создать папку `tests` и хранить в ней тесты для приложения.

Правила именования:

- Файлы: `test_*.py` или `*_test.py`.
- Функции: `test_*`.
- Классы (если используешь): `Test*`.

Assert (Утверждение): Это основа теста. Мы утверждаем, что некое условие истинно.

- `assert 1 == 1` — тест пройдет.
- `assert "Login" in response_text` — проверка вхождения.

Запуск:

- `pytest`

## **Конфигурационный файл** (`pytest.ini`)

`pytest.ini` — это конфигурационный файл для Pytest. Он говорит pytest, как именно запускать тесты в проекте.

Начинается с:

```ini
[pytest]
```

Пример:

```ini
[pytest]
testpaths = tests
pythonpath = src
python_files = test_*.py
python_classes = Test*
python_functions = test_*
addopts = -v
```

<hr />

### `pythonpath` — директории для import

— это настройка, которая говорит Pytest, в какие директории добавить Python при поиске модулей для `import`.

```ini
pythonpath = src
```

Тогда вместо `from src.main import A` -> `from main import A`

<hr />

### `testpaths` — искать тесты в папке

```ini
testpaths = folder
```

— искать тесты в папке `folder`

<hr />

### `python_files` — считать файлами с тестами

```ini
python_files = test_*.py
```

— считать файлами с тестами `test_*.py`

<hr />

### `python_classes` — искать классы

```ini
python_classes = Test*
```

— искать классы, начинающиеся с `Test`

<hr />

### `python_functions` — искать функции

```ini
python_functions = test_*
```

— искать функции, начинающиеся с `test_`

<hr />

### `addopts` — автоматически добавлять опцию при каждом запуске

```ini
addopts = -v
```

— автоматически добавлять опцию `-v` при каждом запуске

## **Параметризация** (выполнение теста с разными вход. данными)

Параметризация в `pytest` — это способ запустить один и тот же тест несколько раз с разными входными данными.

Без параметризации пришлось бы писать несколько тестов:

```Python
def test_add():
    assert add(2, 3) == 5

def test_add_negative():
    assert add(-1, 1) == 0

def test_add_zero():
    assert add(0, 5) == 5
```

С параметризацией это можно записать компактнее:

```Python
import pytest

@pytest.mark.parametrize(
    "a, b, expected",
    [
        (2, 3, 5),
        (-1, 1, 0),
        (0, 5, 5),
    ]
)
def test_add(a, b, expected):
    assert add(a, b) == expected
```

Pytest фактически выполнит три отдельных тест-кейса:

```
test_add[2-3-5]       PASSED
test_add[-1-1-0]      PASSED
test_add[0-5-5]       PASSED
```

## **Группировка тестов**

### По классам

В `pytest` классы удобно использовать именно для логической группировки связанных тестов.

<details>
  <summary>Пример</summary>

```Python
class TestLogin:
    def test_valid_credentials(self):
        ...

    def test_invalid_password(self):
        ...

    def test_empty_login(self):
        ...


class TestRegistration:
    def test_valid_registration(self):
        ...

    def test_existing_email(self):
        ...
```

</details>

Запуск конкретного класса:

```bash
pytest tests/test_auth.py::TestLogin
```

Запуск конкретного теста в классе:

```bash
pytest tests/test_auth.py::TestLogin::test_valid_credentials
```

## "Плохой" vs "Хороший" подход

Плохо:

- Использовать несколько assert в одном тесте для проверки разных, не связанных вещей (если первый упадет, второй даже не запустится).
- Писать тесты, которые зависят друг от друга (Тест 2 работает, только если прошел Тест 1).

Хорошо:

- Соблюдать структуру AAA (Arrange, Act, Assert).
- Давать тестам длинные и понятные имена, описывающие суть проверки.

<hr />

## AAA паттерн

Это стандарт написания тестов:

- **Arrange (Организация)**: настройка окружения, создание данных. Подготовить всё необходимое для теста: данные, объекты, моки, фикстуры.
- **Act (Действие)**: выполнение целевого действия (вызов функции, клик по кнопке). Выполнить **одно основное действие**, которое тестируем.
- **Assert (Проверка)**: сравнение полученного результата с ожидаемым.

> AAA делает тесты проще для чтения: человек сразу понимает: <br/>
> _Что мы подготовили → что сделали → что ожидаем._
