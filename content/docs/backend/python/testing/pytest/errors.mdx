# Обработка исключений (ошибок)

## **Проверка, что исключение возникает**

Тест пройдёт, если наша функция выбросит нужный там [ErrorType](../../exceptions). Если исключения не будет или тип будет другим — тест упадёт.

```Python
import pytest


def test_funcName():
    with pytest.raises(ErrorType):
        funcNameToTest(10, 0)
```

- [ErrorType](../../exceptions) - специальные исключения Python.

import pytest

## **Если исключение ожидается и не ожидается**

Это особенно удобно, когда тестов много и среди них есть как валидные, так и невалидные входные данные.

```Python
import pytest
from contextlib import nullcontext as does_not_raise

@pytest.mark.parametrize("param1,param2,res,expectation", [
    (5,-1,-5,does_not_raise()),
    (5, "-1", -5, pytest.raises(TypeError)),
])
def test_divide():
    with expectation:
        assert funcNameToTest(param1,param2) == res
```

Причём здесь есть важный нюанс: значение `res = -5` во втором случае фактически не проверяется. Если `funcNameToTest(5, "-1")` выбросит `TypeError`, выполнение до `assert` вообще не дойдёт.
