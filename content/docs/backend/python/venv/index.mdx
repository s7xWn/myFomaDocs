# Виртуальное окружение (`venv`)

— это изолированная среда Python, которая позволяет каждому проекту иметь собственные версии библиотек, собственная папка `site-packages` и даже собственный исполняемый файл Python (в рамках одной установленной версии).

## Зачем нужны виртуальные окружения?

Представьте, что у вас есть два проекта:

- **Проект A** требует `requests==2.28.0`
- **Проект B** требует `requests==2.32.3`

Если устанавливать библиотеки глобально, они будут конфликтовать.<br/>
Виртуальные окружения решают эту проблему: каждый проект хранит свои зависимости отдельно.

<hr />

## Создание `venv`

```bash
python -m venv venv
```

```bash
python -m venv .venv
```

Для создания мы запускаем встроенный модуль Python `venv` и создай виртуальное окружение с именем `venv` или `.venv`

:::tip
Имя папки часто тоже `venv`

Или `.venv` (популярен, потому что папка скрыта в Linux/macOS)
:::

## Активация

### Windows — CMD

```CMD
venv\Scripts\activate
```

### Windows — PowerShell:

```PowerShell
.\venv\Scripts\Activate.ps1
```

### Linux / macOS (bash/zsh):

```
source venv/bin/activate
```

## Деактивация

```bash
deactivate
```
