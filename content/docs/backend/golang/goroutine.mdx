Горутина (goroutine) в Go (Golang) — это лёгкий поток выполнения, который позволяет запускать функции параллельно или конкурентно с другими функциями.

Проще говоря, горутина — это способ сказать Go: «Выполни эту функцию независимо от основного кода».

<Callout title='' type='success'>

Главная горутина - `main`

</Callout>

В Go начальный стек одной горутины занимает примерно 2 КБ памяти (в современных версиях Go). Стек горутины может автоматически увеличиваться по мере необходимости.

<Callout title='' type='tip'>

Горутина (Goroutine) — это лёгкая единица конкурентного выполнения в языке Go, реализованная на основе концепции Green Threads (зелёных потоков) и обладающая свойствами Coroutine (корутин).

</Callout>

Для запуска горутины используется ключевое слово `go`

```go
go funcNmae()
```

## Уступить текущий поток другим goroutine - `runtime.Gosched()`

`runtime.Gosched()` в Go — это функция из пакета `runtime`, которая добровольно уступает текущий поток выполнения (goroutine) другим goroutine.

```go
runtime.Gosched()
```

## Гонка данных (Data Race)

Гонка данных (Data Race) в Go — это ситуация, когда несколько горутин одновременно обращаются к одной и той же области памяти,
причём хотя бы одна из них изменяет данные, а доступ не синхронизирован.

<details>
  <summary>Пример</summary>

```go
package main

import (
	"fmt"
	"time"
)

// У команды go есть флаг -race, который позволяет найти гонки данных. Обычно запускают в тестах. Но можно и в go run:
// CGO_ENABLED=1 go run -race ./2-data-race-counter.go
func main() {
	//runtime.GOMAXPROCS(1) // Количество P

	{ // Гонка данных
		var counter int

		for range 10_000 {
			go func() {
				counter++
			}()
		}

		time.Sleep(time.Second)

		fmt.Println(counter)
	}
}
```

</details>

### Исправить гонку данных

#### Использовать 1 поток (`runtime.GOMAXPROCS(1)`)

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

// У команды go есть флаг -race, который позволяет найти гонки данных. Обычно запускают в тестах. Но можно и в go run:
// CGO_ENABLED=1 go run -race ./2-data-race-counter.go
func main() {
	runtime.GOMAXPROCS(1) // Количество P

	{ // Гонка данных
		var counter int

		for range 10_000_000 {
			go func() {
				counter++
			}()
		}

		time.Sleep(time.Second)

		fmt.Println(counter)
	}
}
```

<hr />

#### Использовать Mutex (`mu.Lock()`)

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
    mx := sync.Mutex{}
    var counter int

    for range 100 {
        go func() {
			fmt.Println("Create goroutine")
            mx.Lock() // <- Блокировка
            counter++
			fmt.Println(counter)
            mx.Unlock()
        }()
    }

    time.Sleep(time.Second)

    fmt.Println("Total:",counter)

}

```

<hr />

#### Использовать Atomic

При использовании `time.Sleep()`:

```go
package main

import (
	"fmt"
	"sync/atomic"
	"time"
)

func main() {
    var counter atomic.Int64

    for range 10_000 {
        go func() {
			counter.Add(1)
        }()
    }

    time.Sleep(time.Second)

    fmt.Println("Total:",counter.Load())

}
```

Нужен универсальный способ с `WaitGroup`:

```go
package main

import (
	"fmt"
	"sync"
)

func Init() {
	fmt.Println("Инициализация выполнена")
}

func main() {
	// используется для того, чтобы гарантировать, что определённый код выполнится только один раз,
	// даже если несколько горутин попытаются выполнить его одновременно

	var wg sync.WaitGroup
	var once sync.Once

	for i := 0; i < 5; i++ {
		wg.Add(1)

		go func() {
			defer wg.Done()

			once.Do(Init)

			fmt.Println("Горутина завершена")
		}()
	}

	wg.Wait()
}

```

- `wg.Add(n)` - увеличивает счётчик группы ожидания на `n`.
- `defer` - откладывает выполнение функции до момента завершения текущей функции. <br/>
  т.е. `wg.Done()` выполнится когда наша функция закончит выполнение.
- `wg.Done()` - уменьшает счётчик группы ожидания на `1`.
- `once.Do(funcName)` - выполнит функцию один раз
- `wg.Wait()` - блокирует выполнение текущей горутины до тех пор, пока счётчик WaitGroup не станет равен 0.

## Как устроены Goroutine

Горутина позволяет выполнять функцию независимо от основного потока программы,
приостанавливать и возобновлять её выполнение.
В отличие от системных потоков (OS Threads),
горутины управляются планировщиком Go Runtime,
который распределяет множество горутин между системными потоками по модели M:N.

Go использует модель планирования G-M-P

```
GMP

    [G — Goroutines]
Лёгкие задачи выполнения
    (G1 G2 G3 G4 G5)
        ||
        \/
    [P — Processor]
Логический ресурс планировщика Go
        ||
        \/
    [M — Machine (OS Thread)]
Системный поток операционной системы
```

Go Runtime распределяет множество горутин между меньшим или равным числом одновременно работающих OS Threads (в зависимости от настроек и состояния runtime).

<hr />

### Горутина vs обычный поток (Thread)

| Характеристика                 | Coroutine                              | Green Thread          | Goroutine                        |
| ------------------------------ | -------------------------------------- | --------------------- | -------------------------------- |
| Приостановка выполнения        | Да                                     | Зависит от реализации | Да                               |
| Переключение                   | Обычно кооперативное                   | Зависит от реализации | Runtime, в том числе вытесняющее |
| Планировщик                    | Может отсутствовать или быть в runtime | User-space runtime    | Go Runtime                       |
| Выполнение на нескольких ядрах | Зависит от реализации                  | Зависит от реализации | Да                               |
| OS Thread                      | Не обязательно                         | Не обязательно        | Выполняется на OS Thread         |

### Сколько потоков создаётся при запуске - `runtime.GOMAXPROCS(0)`

Количество `P` по умолчанию равно `GOMAXPROCS`, который в современных версиях Go обычно определяется количеством доступных CPU.

<Callout title='' type=''>

`GOMAXPROCS` не является обычной переменной окружения Go, которую обязательно можно увидеть через `go env`.

Она задаётся во время выполнения программы.

```go
package main

import (
    "fmt"
    "runtime"
)

func main() {
    fmt.Println("NumCPU:", runtime.NumCPU())
    fmt.Println("GOMAXPROCS:", runtime.GOMAXPROCS(0))
}
```

</Callout>

#### Установить `GOMAXPROCS`

Через переменную окружения:

```bash
GOMAXPROCS=4 go run main.go
```

в коде:

```go
runtime.GOMAXPROCS(4)
```

## Пример (файл)

```go
package main

import (
	"fmt"
	"runtime"
	"time"
)

func hello() {
	fmt.Println("Hello 1")
}

func main() {
	runtime.GOMAXPROCS(4) // Количество P, которые будут использоваться для выполнения горутин
	runtime.Gosched()     // Передача управления другим горутинам

	{ // Запуск функции в горутине
		go hello()

		time.Sleep(time.Second)
	}

	{ // Запуск анонимной функции в горутине
		go func() {
			fmt.Println("Hello 2")
		}()

		time.Sleep(time.Second)
	}

	{ // То же самое
		fn := func() {
			fmt.Println("Hello 3")
		}

		go fn()

		time.Sleep(time.Second)
	}
}
```

`WaitGroup`:

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func main() {
	{ // Одновременный запуск медленных операций
		var wg sync.WaitGroup

		wg.Add(3)

		now := time.Now()

		go func() {
			defer wg.Done()
			time.Sleep(time.Second) // Service A
		}()

		go func() {
			defer wg.Done()
			time.Sleep(time.Second) // Service B
		}()

		go func() {
			defer wg.Done()
			time.Sleep(time.Second) // Service C
		}()

		wg.Wait()

		fmt.Println("Время выполнения:", time.Since(now))
	}
}
```
