В Go нет строгого требования использовать `snake_case` для названий директорий. Однако есть общепринятые соглашения.

Рекомендация:

- Директории — `snake_case` или `lowercase` (предпочтительнее lowercase без разделителей).
- Файлы — `snake_case`.
- Пакеты — `lowercase`, желательно одним словом.
- Экспортируемые идентификаторы — `PascalCase`.
- Неэкспортируемые идентификаторы — `camelCase`.

```
myapp/
├── cmd/
│   └── app/
│       └── main.go              # Точка входа приложения
│
├── internal/                    # Ограничения импорта Go-пакетов за пределами определённой области проекта
│
├── migrations/
│   ├── 001_create_users.up.sql
│   └── 001_create_users.down.sql
│
├── api/
│   └── openapi.yaml
│
├── pkg/                          # Публичные переиспользуемые пакеты
│
├── configs/
│   └── config.yaml
│
├── deployments/
│   ├── Dockerfile
│   └── docker-compose.yaml
│
├── scripts/
│
├── test/
│   ├── integration/
│   └── e2e/
│
├── .env.example
├── .gitignore
├── Makefile
├── go.mod
├── go.sum
└── README.md
```

- `myapp/cmd/app` - обычно разные названия: app, api, server

## `internal/`

### Тесты

`internal/packageName`:

```
file.go
file_test.go
```

- Внутри пакета `package packageName`:
  - Доступ к экспортируемым идентификаторам.
  - Доступ к неэкспортируемым идентификаторам (private-аналогам).
  - Можно тестировать внутреннюю реализацию.
- Снаружи пакета `package packageName_test`:
  - Доступ только к экспортируемым идентификаторам.
  - Тестирование через публичный API пакета.
  - Проверка поведения без привязки к внутренней реализации.
  - Требуется импортировать тестируемый пакет.
