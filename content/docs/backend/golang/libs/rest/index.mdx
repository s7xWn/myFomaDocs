Для создания REST API на Go я рекомендую использовать [net/http](../../std-libs/net-http.mdx) или [Chi](./chi.mdx) в качестве основы, а остальные библиотеки подбирать под задачи проекта.

В Go нет необходимости использовать тяжёлый фреймворк: стандартная библиотека уже предоставляет хороший HTTP-сервер, маршрутизацию и middleware-интерфейсы.

[Chi](./chi.mdx), [Gin](./gin.mdx) и [Echo](./echo.mdx) — популярные библиотеки для разработки HTTP-сервисов и REST API на Go.

Все три решения позволяют реализовать маршрутизацию, middleware, обработку HTTP-запросов и ответов. Однако они отличаются архитектурой, уровнем абстракции и набором встроенных возможностей.

Основные концепции:

- **[Chi](./chi.mdx)** — минималистичный HTTP-роутер, максимально близкий к стандартному `net/http`.
- **[Gin](./gin.mdx)** — производительный веб-фреймворк с большим количеством готовых возможностей.
- **[Echo](./echo.mdx)** — полноценный HTTP-фреймворк с лаконичным API и встроенными инструментами.

| Характеристика                    | Chi                | Gin                    | Echo                   |
| --------------------------------- | ------------------ | ---------------------- | ---------------------- |
| Тип                               | Router             | Framework              | Framework              |
| Основа                            | `net/http`         | Собственный Context    | Собственный Context    |
| Производительность                | Высокая            | Очень высокая          | Очень высокая          |
| Простота                          | Высокая            | Высокая                | Высокая                |
| Middleware                        | Да                 | Да                     | Да                     |
| JSON binding                      | Нет                | Да                     | Да                     |
| JSON response helpers             | Нет                | Да                     | Да                     |
| Валидация                         | Внешние библиотеки | Интеграция с validator | Интеграция с validator |
| Группировка маршрутов             | Да                 | Да                     | Да                     |
| Совместимость с `net/http`        | Нативная           | Через адаптеры         | Через адаптеры         |
| Централизованная обработка ошибок | Самостоятельно     | Через middleware       | Встроенный механизм    |
| Экосистема                        | Хорошая            | Очень большая          | Хорошая                |

## Chi

| [GitHub](https://github.com/go-chi/chi) |
| --------------------------------------- |

Chi — минималистичный HTTP-роутер, построенный вокруг стандартной библиотеки Go.

Его основная идея — не создавать лишних абстракций и использовать стандартный HTTP API.

### Преимущества

- Полная совместимость с `net/http`.
- Использование стандартных `http.Handler` и `http.HandlerFunc`.
- Удобная группировка маршрутов.
- Поддержка middleware.
- Небольшое количество зависимостей.
- Простая интеграция с другими Go-библиотеками.
- Удобен для Clean Architecture и Hexagonal Architecture.

### Недостатки

- Нет встроенного JSON binding.
- Нет встроенной валидации запросов.
- Обработку ошибок и HTTP-ответов нужно организовывать самостоятельно.
- Для полноценного API потребуется больше инфраструктурного кода.

### Пример

```go
package main

import (
    "encoding/json"
    "net/http"

    "github.com/go-chi/chi/v5"

)

func main() {
r := chi.NewRouter()

    r.Get("/users/{id}", func(w http.ResponseWriter, r *http.Request) {
        id := chi.URLParam(r, "id")

        w.Header().Set("Content-Type", "application/json")
        json.NewEncoder(w).Encode(map[string]string{
            "id": id,
        })
    })

    http.ListenAndServe(":8080", r)

}
```

### Когда использовать

- Микросервисы.
- REST API.
- Проекты с Clean Architecture.
- Проекты с Hexagonal Architecture.
- Backend с собственной инфраструктурой.
- Проекты, где важны независимость от фреймворка и контроль над HTTP-слоем.

## Gin

| [GitHub](https://github.com/gin-gonic/gin) |
| ------------------------------------------ |

Gin — один из наиболее распространённых веб-фреймворков для Go.

Он предоставляет собственный `gin.Context`, который упрощает работу с HTTP-запросами, ответами и параметрами.

### Преимущества

- Удобный JSON binding.
- Интеграция с `go-playground/validator`.
- Удобная обработка HTTP-ошибок.
- Middleware и группы маршрутов.
- Большое сообщество.
- Хорошая документация.
- Большое количество примеров и готовых решений.
- Высокая производительность.

### Недостатки

- Используется собственный `gin.Context`.
- Для интеграции некоторых библиотек могут потребоваться адаптеры.
- Больше абстракций по сравнению с Chi.
- HTTP-слой сильнее привязан к конкретному фреймворку.

### Пример

```go
package main

import (
    "net/http"

    "github.com/gin-gonic/gin"
)

type User struct {
    Name string \`json:"name" binding:"required"\`
}

func main() {
    r := gin.Default()

    r.POST("/users", func(c *gin.Context) {
        var user User

        if err := c.ShouldBindJSON(&user); err != nil {
            c.JSON(http.StatusBadRequest, gin.H{
                "error": err.Error(),
            })
            return
        }

        c.JSON(http.StatusCreated, user)
    })

    r.Run(":8080")
}
```

### Когда использовать

- REST API.
- Backend для веб-приложений.
- Проекты с большим количеством endpoint'ов.
- Командная разработка.
- Проекты, где важны готовые инструменты и большая экосистема.

## Echo

| [GitHub](https://github.com/labstack/echo) |
| ------------------------------------------ |

Echo — полноценный HTTP-фреймворк, концептуально похожий на Gin.

Он предоставляет собственный `echo.Context` и набор встроенных инструментов для создания HTTP API.

### Преимущества

- Удобная маршрутизация.
- Встроенные JSON binding и response helpers.
- Middleware для CORS, JWT, логирования и других задач.
- Централизованная обработка ошибок.
- Поддержка групп маршрутов.
- Хорошая производительность.
- Лаконичный API.

### Недостатки

- Используется собственный `echo.Context`.
- Экосистема меньше, чем у Gin.
- Некоторые возможности требуют сторонних пакетов.
- Между мажорными версиями возможны breaking changes.

### Пример

Пример ниже использует API Echo v4.

```go
package main

import (
    "net/http"

    "github.com/labstack/echo/v4"
)

type User struct {
    Name string \`json:"name"\`
}

func main() {
    e := echo.New()

    e.POST("/users", func(c echo.Context) error {
        user := new(User)

        if err := c.Bind(user); err != nil {
            return echo.NewHTTPError(
                http.StatusBadRequest,
                err.Error(),
            )
        }

        return c.JSON(http.StatusCreated, user)
    })

    e.Logger.Fatal(e.Start(":8080"))
}
```

### Когда использовать

- Полноценные HTTP API.
- Сервисы с централизованной обработкой ошибок.
- Проекты, которым нужны встроенные HTTP-возможности.
- Проекты, где важен баланс между простотой и функциональностью.

## Производительность

Все три библиотеки достаточно производительны для большинства backend-приложений.

В одном из сравнительных benchmark-тестов на Apple M4 Pro с Go 1.25.8 были получены следующие результаты:

| Библиотека | Время на операцию | Аллокации |
| ---------- | ----------------: | --------: |
| Gin        |          9,944 ns |         0 |
| Echo       |         11,072 ns |         0 |
| Chi        |         94,376 ns |       740 |

Меньшее время выполнения означает лучший результат.

**Важно:** это конкретный benchmark маршрутизации с 203 маршрутами, а не полноценное измерение производительности REST API. Результаты нельзя напрямую переносить на реальные приложения.

В production-приложениях узкими местами гораздо чаще становятся:

- PostgreSQL и другие базы данных.
- Redis.
- Сетевые запросы.
- JSON-сериализация.
- Бизнес-логика.

Поэтому выбирать фреймворк исключительно по benchmark-результатам не стоит.

## Архитектурные различия

Одно из главных различий между библиотеками — степень привязки HTTP-слоя к конкретному фреймворку.

| Критерий                          | Chi            | Gin              | Echo           |
| --------------------------------- | -------------- | ---------------- | -------------- |
| Стандартный HTTP Handler          | Да             | Через адаптеры   | Через адаптеры |
| Собственный Context               | Нет            | Да               | Да             |
| Стандартные middleware            | Да             | Через адаптеры   | Через адаптеры |
| Централизованная обработка ошибок | Самостоятельно | Через middleware | Встроенная     |
| Контроль над HTTP                 | Максимальный   | Средний          | Высокий        |
| Количество готовых решений        | Небольшое ядро | Большое          | Большое        |

### Почему совместимость с net/http важна

Chi позволяет использовать стандартные Go-обработчики:

```go
func GetUser(
    w http.ResponseWriter,
    r *http.Request,
) {
    // Business logic
}
```

Это упрощает разделение ответственности и позволяет не привязывать бизнес-логику к конкретному HTTP-фреймворку.

Gin и Echo используют собственные контексты, поэтому их API сильнее влияет на HTTP-слой приложения.

При этом все три решения позволяют строить хорошую многослойную архитектуру.

## Итоговая рекомендация

Для нового production backend на Go я бы расставил приоритеты следующим образом.

### Chi — выбор для минимализма и архитектурной независимости

Chi хорошо подходит для проектов, в которых хочется использовать идиоматичный Go, стандартный HTTP API и Clean Architecture.

Основные преимущества:

- Минимум абстракций.
- Нативная совместимость с `net/http`.
- Простота тестирования.
- Независимость бизнес-логики от HTTP-фреймворка.
- Хорошая расширяемость.

### Gin — выбор для скорости разработки

Gin подходит, если важны распространённость, готовые инструменты и большое количество примеров.

Основные преимущества:

- Удобный JSON binding.
- Встроенные возможности.
- Большая экосистема.
- Хорошая документация.
- Высокая производительность.

### Echo — выбор для полноценного HTTP-фреймворка

Echo предлагает удобный API и встроенные возможности для разработки HTTP-сервисов.

Основные преимущества:

- Лаконичный интерфейс.
- Удобная маршрутизация.
- Централизованная обработка ошибок.
- Встроенные HTTP-инструменты.

## Заключение

Рекомендация для нового Go backend — **Chi**.

Он хорошо сочетается с философией Go: использовать стандартную библиотеку там, где её возможностей достаточно, и добавлять абстракции только тогда, когда они действительно необходимы.

При этом Gin будет отличным выбором, если приоритетом является скорость разработки, а Echo — если нужен полноценный HTTP-фреймворк с удобными встроенными возможностями.

Главное — не выбирать библиотеку только по benchmark-тестам. Архитектура приложения, качество кода, работа с базой данных и правильная организация бизнес-логики гораздо сильнее влияют на долгосрочную поддержку и производительность проекта.
