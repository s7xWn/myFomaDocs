Одна из главных особенностей Go — приложение обычно компилируется в самостоятельный исполняемый бинарный файл. В отличие от многих языков, для запуска которого нужна установленная среда выполнения (например, JVM для Java или интерпретатор Python), Go-приложение в большинстве случаев не требует установки Go на сервере.

## Компиляция в бинарник

В этот бинарник компилятор помещает:

- Машинный код приложения.
- Код используемых Go-библиотек.
- Необходимые части стандартной библиотеки Go.
- Runtime Go (управление памятью, планировщик горутин, сборщик мусора и т. д.).

То есть большая часть необходимого для работы приложения уже находится внутри одного файла.

### Почему не нужны зависимости?

Go использует подход, при котором зависимости на этапе компиляции фактически включаются в итоговый бинарник.

Например, если приложение использует:

```go
import (
    "net/http"
    "encoding/json"
    "github.com/gin-gonic/gin"
)
```

То код `Gin` и используемые части стандартной библиотеки будут включены в итоговый бинарник.

На сервере не нужно:

- Устанавливать Go.
- Устанавливать сторонние Go-библиотеки.
- Выполнять `go install` или `go mod download`.
- Копировать исходный код приложения.

Достаточно скопировать бинарник и запустить его.

<Callout title='Важно' type='tip'>

Это не означает, что бинарник абсолютно независим от операционной системы. Он всё ещё может зависеть от системных библиотек, например `glibc` или `musl`, а также от конфигурационных файлов, сертификатов и других внешних ресурсов.

</Callout>

## Запуск на Alpine

Это особенно полезно при использовании Docker.

Alpine Linux — минималистичный Linux-дистрибутив, который использует библиотеку `musl` вместо `glibc` (характерной для Debian и Ubuntu).

Если приложение собрано как статический бинарник, ему не нужно искать системные динамические библиотеки. Поэтому его можно запускать даже в очень минимальном контейнере.
