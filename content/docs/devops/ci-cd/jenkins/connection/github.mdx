## SSH key

Создаём SSH-ключ для Jenkins

```bash
sudo -u jenkins ssh-keygen -t ed25519 -C "jenkins@$(hostname)"
```

<details>
  <summary>Подробнее</summary>

Когда спросит:

- `Enter file in which to save the key:` -> Enter
- `Enter passphrase:` -> Enter

В результате должны появиться:

```
/var/lib/jenkins/.ssh/id_ed25519
/var/lib/jenkins/.ssh/id_ed25519.pub
```

Проверить:

```bash
sudo -u jenkins ls -la /var/lib/jenkins/.ssh/
```

</details>

Получаем публичный ключ

```bash
sudo cat /var/lib/jenkins/.ssh/id_ed25519.pub
```

Вот эту строку целиком нам понадобится добавить в GitHub.

:::danger
Не показывать никому содержимое: `/var/lib/jenkins/.ssh/id_ed25519` <br/>
Это приватный ключ.
:::

### Создание Deploy key для GitHub

Открыть repository на GitHub. <br/>
Settings → Deploy keys → Add deploy key

- **Title**: Jenkins
- **Key**: содержимое `sudo cat /var/lib/jenkins/.ssh/id_ed25519.pub`

<hr />

### Проверка SSH-доступ

```bash
sudo -u jenkins ssh -T git@github.com
```

При первом подключении может появиться:

```
The authenticity of host 'github.com' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Ответ: `yes`, после GitHub ответит примерно: `Hi username! You've successfully authenticated, but GitHub does not provide shell access.`

Это успешный результат.

<hr />

### Проверка repository

```bash
sudo -u jenkins git ls-remote git@github.com:USERNAME/REPOSITORY.git
```

<hr />

### Ключ в Jenkins Credentials

Здесь есть важный момент: ключ мы создали для пользователя `jenkins`, но **Jenkins Pipeline** всё равно лучше подключать через **Credentials**, а не рассчитывать на системный SSH-ключ.

В Jenkins: Manage Jenkins → Credentials → System → Global credentials → Add Credentials → SSH Username with private key

- **Username**: `git`
- **Private Key**: `Enter directly` + `sudo cat /var/lib/jenkins/.ssh/id_ed25519`
- **ID**: `github-ssh`
