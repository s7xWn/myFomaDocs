## Multi-stage build

Multi-stage build - это подход, при котором Docker-образ собирается в два этапа (или более), чтобы итоговый образ был меньше, безопаснее и не содержал лишних инструментов для сборки.

Представим, что у есть приложение на Go, Java или Node.js.

Обычно для его сборки нужны:

- Компилятор.
- Зависимости для разработки.
- Инструменты сборки.
- Исходный код.

Но для запуска приложения всё это уже не нужно. Нужен только готовый исполняемый файл и необходимые runtime-зависимости.

Поэтому процесс разделяется на несколько этапов.

<details>
  <summary>Разбор примера на Go</summary>

```dockerfile
# STAGE 1 — BUILD
FROM golang:1.24 AS builder

WORKDIR /app

COPY go.mod go.sum ./
RUN go mod download

COPY . .

RUN CGO_ENABLED=0 GOOS=linux go build -o app .


# STAGE 2 — RUNTIME
FROM alpine:3.21

WORKDIR /app

# Забираем бинарник из первого этапа
COPY --from=builder /app/app .

# Запускаем приложение
CMD ["./app"]
```

Первый этап:

```dockerfile
FROM golang:1.24 AS builder

WORKDIR /app

COPY go.mod go.sum ./
RUN go mod download

COPY . .

RUN CGO_ENABLED=0 GOOS=linux go build -o app .
```

- Создаём контейнер с Go-компилятором.
- Устанавливаем зависимости.
- Копируем исходный код.
- Компилируем приложение в бинарный файл app.

Второй этап:

```dockerfile
FROM alpine:3.21

WORKDIR /app

# Забираем бинарник из первого этапа
COPY --from=builder /app/app .

# Запускаем приложение
CMD ["./app"]
```

- В нём нет Go-компилятора.
