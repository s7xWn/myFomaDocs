Kubernetes (K8s) — это платформа для автоматизации развёртывания, управления и масштабирования приложений в контейнерах.

Если совсем просто: Kubernetes — это система, которая управляет множеством серверов и автоматически следит за тем, чтобы твоё приложение работало стабильно.

<Callout title='' type=''>

- Docker — инструмент для создания и запуска контейнеров.
- Kubernetes — инструмент для управления приложениями, работающими в контейнерах.

</Callout>

Он автоматизирует такие вещи, как:

- Запуск приложений.
- Перезапуск приложений, если они упали.
- Распределение приложений по серверам.
- Масштабирование (например, запустить 10 копий вместо 2).
- Управление сетями и доступом между приложениями.

<div className="hr-decor">✦</div>

## Cluster

Кластер — это группа серверов, объединённых для совместной работы под управлением Kubernetes.

Вместо того чтобы запускать приложение на одном сервере, можно использовать несколько серверов.

Состоит из:

- Управляющей ноды (Control Plane) — управляет кластером.
- Рабочих нод (Worker Nodes) — на них запускаются приложения.

<div className="hr-decor">✦</div>

## Node

Нода — это сервер (физический или виртуальный), на котором работает Kubernetes.

На ноде есть:

- CPU — вычислительная мощность.
- RAM — оперативная память.
- Disk — диск.
- Kubelet — агент Kubernetes, который следит за запущенными подами на этой ноде.
- Container runtime — например, containerd, который запускает контейнеры.

Нода может быть виртуальной машиной в облаке или физическим сервером.

<div className="hr-decor">✦</div>

## Pod

Pod — это минимальная единица запуска в Kubernetes, которую Kubernetes планирует (schedule) на Node и управляет её жизненным циклом.

Kubernetes обычно запускает не контейнер напрямую, а Pod, внутри которого находится контейнер/ы.

<Callout title='' type='tip'>

Обычно:

- 1 Pod = 1 основной контейнер — наиболее распространённый вариант.
- 1 Pod = несколько контейнеров — если они тесно связаны между собой.

</Callout>

<hr />

### Container vs Pod

Kubernetes работает с Pods, а не с отдельными контейнерами, потому что Pod обеспечивает:

| Возможность   | Описание                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------- |
| Общий Network | Контейнеры внутри Pod разделяют сеть и IP                                                      |
| Общие Volumes | Контейнеры могут обмениваться файлами                                                          |
| Lifecycle     | Контейнеры управляются в рамках одного Pod                                                     |
| Scheduling    | Kubernetes размещает Pod на Node целиком                                                       |
| Isolation     | Pods изолированы друг от друга на уровне сетевых и других ресурсов (в зависимости от настроек) |

### Pod с Istio Sidecar

При использовании Istio в классическом режиме Sidecar Injection Pod обычно содержит минимум два контейнера:

1. App — основное приложение.
2. Envoy — прокси Istio.
